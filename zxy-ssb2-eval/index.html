V2 到底怎样评分（≤150字速答）

两条独立链路。非可视化（Financial_Model / Template / Debugging）：比对 agent 输出与 golden，仅在 answer_position 圈定的单元格内逐格比，数值走 1% 容差、公式比串、颜色比 RGB；每题拆成"该改的格(modification)"与"不该动的格(regression)"两组命中率；任务级 Accuracy 全有或全无（两组都满分才记 1）。可视化：Windows 上用 Excel/WPS COM 把图导成 PNG，交 VLM(glm-4.6v) 按专家 rubric 逐条判 PASS/FAIL，每题分=通过条目占比（连续）。总分=各题分按类别求平均。

二、复现最易犯的 8 个错误

  1. 数据根路径错位。agent 读 data/spreadsheetbench-v2/<Cat>（README L85），但 evaluation.py 读 <root>/data/<Cat>（L13-14,473，少一层）。后果：照 README 直接跑评测 FileNotFound。核查：把 dataset 同时放到 data/<Cat> 或改 --dataset 路径。
  2. 忘了刷新缓存值。openpyxl 以 data_only=True 读缓存（L362），公式格若未经 LibreOffice 重算则读成 None。后果：公式题几乎全判错、分数虚低。核查：产出后必跑 open_spreadsheet.py --dir_path。
  3. 以为 answer_position 之外也算分。只有 answer_position 圈定的格参与判分（L378-401）。后果：误判"改坏了别处也会扣分"。核查：读 dataset.json 的 answer_position 字段确认范围。
  4. 把 Accuracy 当连续分。任务级 Acc 全有或全无——reg 与 mod 两组都满分才 1（L458）。后果：错报平均。核查：Modif. 才是连续、Acc 是 0/1 任务占比。
  5. 把可视化 Acc 当"过 70% 任务比例"。Table 3 的 Viz Acc = 平均 rubric 通过率（caption L329-331），代码里 >0.7 的二值 acc 是另一个数、不在论文正表。后果：口径张冠李戴。核查：报 all_task_avg_score，不是 acc。
  6. 忽略 99.8% regression 阈值与容差。reg_ratio≥0.998 视作满分（L456）、数值 1% 容差（L38-102）、#DIV/0!≡N/A 等价。后果：误以为"严格逐格完全一致"。核查：读 compare_cell_value。
  7. interaction_turns 静默记 0。只有 outputs 目录路径含 /output_excel/ 才会去 /spreadsheet/ 找 .traj（L482）。后果：轮数统计全 0。核查：按约定命名输出目录。
  8. 在 Linux 上跑可视化评测。导图依赖 Windows win32com + Excel/WPS，判分依赖 VLM API key（L53-57）。后果：无图/全 0。核查：可视化半必须 Windows + glm-4.6v key。

三、整体链路（全局 → 局部）

dataset.json→只读挂载输入 xlsx→agent (bash/view_xlsx/submit, ≤50 turns)→{id}_output.xlsx→LibreOffice 重算缓存→evaluation.py / run_visual_vlm→report.json

评分从一份 dataset.json 契约开始：每题含 id / instruction / spreadsheet_path / golden_response_path（README L38-41），非可视化题还强依赖一个 README 未列全的字段 answer_position（evaluation.py L442）——它用 'Sheet'!A1:K52 形式圈定"参与判分的单元格范围"，可逗号分隔多段。agent 只拿到 instruction + 只读的输入 xlsx，用三个工具（bash / view_xlsx / submit；config 文案误写 four tools）在 50 轮内产出 {id}_output.xlsx。产出后必须先用 LibreOffice headless 重算（open_spreadsheet.py，UNO 端口 2002，calculateAll 后存回 L112-209），否则 openpyxl 以 data_only=True 读缓存会把未重算的公式格读成 None（evaluation.py L362），公式题全判错。最后非可视化走 evaluation.py、可视化走 run_visual_vlm_checklist_eval.py，各自吐出 report.json。

四、非可视化判分（代码逐步还原 + 论文 vs 代码）

五步链路（evaluation.py）：

①定位 parse_answer_position(L188) 把 answer_position 拆成 Sheet!Range 段，generate_cell_names(L242) 展开成每一个具体单元格名。

②分组 classify_cells_by_modification(L282) 比对 input vs golden：相同的格 = regression（不该动），不同的格 = modification（该改）。这一步决定了"改对了多少"和"有没有误伤别处"两组指标。

③比对 compare_cell_value(L38) 比 output vs golden：数值走 1% 相对容差（tolerance=0.01，一端为 0 用绝对误差，值先 round(2)）；公式比串但忽略 $/大小写/=+ 前缀（L91,L171）；日期转 Excel 浮点；None≈0≈''；#DIV/0!≡N/A 等 not-meaningful 值互相等价。

④特判 仅 Debugging 按路径触发（L431-436）：路径含 Color → with_font_color（比值 + 字体 RGB 末 6 位，主题色解析 L106）；含 Embedded → with_formula（比公式串）。

⑤判题 reg_ratio=reg对/reg总、mod_ratio=mod对/mod总（L453）；reg_ratio≥0.998 视作 1.0（L456）；accuracy=1.0 当且仅当 reg==1.0 且 mod==1.0，否则 0（L458）——任务级全有或全无。

聚合（L549-561）：modification_accuracy = 各题 mod_ratio 均值（排除 output 缺失题）；accuracy = 各题 0/1 均值（含缺失题计 0，分母 = 全部题）。所以 Modif. 是连续分、Acc 是 0/1 任务占比，两者分母还不一样。

论文 vs 代码的关键差异：论文 §2.4 L315-321 说 Accuracy 是"every cell match"（逐格完全匹配才记 1）。代码里的"match"实为 1% 容差 + 99.8% regression 阈值 + not-meaningful 等价 + 公式/颜色子模式。口头念"完全一致"会误导——它并不严格逐格字节相等。

实测验证（[本地脚本路径]，合成工作簿）：gold=100 时 out=100.5 通过 / out=102 失败（1% 边界）；regression 格被改动→即便 mod 满分，Acc 仍=0；reg 500/501=0.998→记满分；#DIV/0!≡N/A→通过。全部与代码推断一致。

论文附录真实例：Case1 Debugging，Modif=0.8974 但 H48（gold 1094.14 / agent 1259.34）未全中 → Acc=0（L1292）；Case3 Financial Modeling，公式 =(F95+F90)/F103 vs gold =F90/F103，L37 算得 0.4591 vs 0.2265，Modif=0.8824（L1358）。

五、可视化判分（三个"分数"切勿混淆）

可视化走 run_visual_vlm_checklist_eval.py：① ChartExporter 用 win32com（Excel/WPS COM，DispatchEx L281）把 xlsx 里每个 ChartObject 导成 PNG（L350），多图拼接（L456）——必须 Windows（WIN32COM_AVAILABLE L53-57，本 Linux 环境不可运行）。② VLM（glm-4.6v）按 system prompt 对每条 criterion 判 PASS/FAIL（L598-612），分两维：Data Correctness + Format Compliance（论文 L1149-1155）。③ 单题 final_score = passed_items / total_expected（L723）——通过条目占比，连续 [0,1]。

六、异常/缺失如何计分

两条链路都是"缺失=0 分且计入分母，不跳过、不中断"。非可视化：output 不存在→missing=True（L354,444），该题 Acc=0 计入 acc_scores 分母（L553），但其 reg/mod_ratio 从 Modif. 均值分母剔除（L551-552）；openpyxl 打开异常或 worker 崩→stats 全 0→Acc=0（L446-450,536-543）。可视化：图缺失/VLM 报错/导不出图→{'error', score 0}（L579,632），build_summary note 明示（L1385）"Missing/skipped/unfinished 一律 score=0、acc=0 计入 total_tasks"。真实例 Case6：sunburst 用 XML 注入生成→评测报 "no chart objects" → 整题 0（L1403）。

七、对 某表格 Agent 产品 线上 query 评估的启示

SSB-v2 把评分拆成两档，这个二分法可直接套到 某表格 Agent 产品：(I) 可确定判定（非可视化）= golden 定位 target cells + answer_position 限范围 + 容差/等价 + 任务级判定；(II) 不可规则化（可视化）= 专家 rubric + VLM 二值 PASS/FAIL + 连续通过率。

可直接迁移：

(a) 锚点式 golden——不比整份输出，像 answer_position 一样只圈定"必须正确的判定锚点"（关键字段/结论/数值）。线上 query 蒸馏时顺手标注这些锚点，即可做确定性判分。

(b) 回归位保护——像 regression cells 一样校验"不该改的地方没被改"（线上 = 用户原数据/上下文没被破坏）。

(c) 容差与等价类（1% / #DIV0!≡N/A）——对应 某表格 Agent 产品 答案的近似等价归一。

(d) 开放/多模态输出走 rubric + LLM/VLM-judge，报连续通过率而非只报二值。

需改造 / 不适用：

(1) SSB 有唯一 golden 文件，线上 query 多为开放答案、无单一标准解——须先把 query 分成"可判定"（有唯一锚点）与"开放"（走 rubric）两档。

(2) 任务级全有或全无过严，某表格 Agent 产品 更适合 modification 式连续分 + 分维度 rubric。

(3) >0.7 二值阈值是人为设定，迁移前须用标注集校准。

(4) VLM-judge 有噪声（论文 L826 自承 rubric 噪声），需人审校准。

改造样例：线上 query『把这张销售表按区域做个柱状图并算出各区域同比』→拆成 (i) 确定性档：'各区域同比'写入指定单元格，用 answer_position + 1% 容差自动判分；(ii) rubric 档：'柱状图'走 checklist（图表类型=柱状 / 坐标轴标签 / 区域齐全 / 数值正确），VLM 判 PASS/FAIL 出连续分。落地：复用 evaluation.py 的 cell 比对内核做确定性档，复用 run_visual_... 的 checklist+VLM 内核做开放档，两档分别产出"精确率（连续）"与"通过率（连续）+ 校准二值"。

八、四条防误读边界

  1. 规模与分类。V2 = 321 任务（均值 11.8 工作表、593.5 单元格修改）。论文三大类 generation / debugging / visualization，代码/数据四目录 Template / Financial_Model / Debugging / Visualization（generation = {FM, Template}）。禁止引用 V1（912 题）——V2 无此口径。各类精确任务数需 dataset.json 实测【待确认，本环境无外网未下载】。
  2. "every cell match" ≠ 字节相等。论文说逐格匹配，代码实为 1% 容差 + 99.8% regression 阈值 + not-meaningful 等价 + 公式/颜色模式。
  3. Viz Acc 是连续通过率。Table 3 的 Viz "Acc."= 平均 rubric 通过率（all_task_avg_score），不是 >0.7 二值 acc，也不是 Figure 11 的 76.2。
  4. 复现前处理三件套。先用 open_spreadsheet 重算 input+golden（README L25）→ agent 产出后再 LibreOffice 刷新缓存 → 可视化半需 Windows + COM + VLM key，缺一不可。

十、下一步：评测我自己的 agent

第一步，把线上 query 分成"可判定档"（标注锚点单元格 + 回归位 + 容差规则，直接复用 evaluation.py 的 cell 比对内核做自动判分）与"开放档"（写两维 rubric，复用 run_visual_... 的 checklist+VLM 内核）。第二步，先在一小批带人工标注的 query 上校准 VLM-judge 与 >0.7 阈值，确认 judge 噪声可控再放量。第三步，报告时坚持"连续分（Modif./通过率）为主、二值 Acc 为辅"的双口径，避免把 SSB 论文那种"全有或全无 Accuracy"的过严口径直接搬到开放答案场景。
