结论速览 TL;DR

一句话：这不是一篇"炫模型"的报告，而是一本"如何从零训练一个前沿推理 MoE"的工程手册。核心论点是把模型研发变成一台 hill-climbing machine（爬山机器）——数据管线、训练基础设施、RL 环境与奖励、评测套件、安全测试全部打通成一个可测量、可重复、可持续爬升的经验优化闭环。全篇贯穿一句方法论：每个决策都要能用缩放梯子 / 消融 / 评测来验证，不走捷径。

模型身份：35B 激活 / 1T 总参的稀疏 MoE，78 层，8K GB200 从零预训练 30T token + 3.55T mid-training，完全不蒸馏任何第三方模型、不用 LLM 合成数据。成绩：AIME 2025 97.0%、AIME 2026 94.5%、LiveCodeBench v6 87.7%、SWE-Bench Pro 52.8%，与 Claude Sonnet 4.6 同档位竞争。作者诚实定性："it does not lead the field, but it delivers consistently strong performance across a broad set of benchmark categories."

块 1 · 模型架构（§2.1）

整体是 decoder-only Transformer，78 层，两处"交替"设计是全篇架构的灵魂（Figure 2 原文）：

"we interleave high-sparsity MoE layers with small dense FFNs, and global attention with local attention. ... 8 of 512 experts are activated per token in a compressed latent space."

稀疏 MoE：LatentMoE 8/512，2× 压缩

  • 512 专家，每 token 只激活 8 个 → 这就是"1T 总参 / 35B 激活"的来源：绝大多数参数不参与单 token 前向，算力只花在被路由到的 8 个专家上。
  • latent / compressed space：专家的 up/down 投影在压缩的低维潜空间做，相当于给 MoE 层内置降维，省显存省算力。
  • dropless MoE：不做 token dropping（传统 MoE 超容量会丢 token），所有 token 都被路由到位 → 训练信号不损失。
  • 全局 batch 负载均衡损失（GShard 式辅助 loss，RL 阶段系数 1e-5、自蒸馏 1e-2）：在全局 batch而非单卡局部上做均衡，防止少数专家被挤爆。
  • 高稀疏 MoE 层与小 dense FFN 交替：不是每层都 MoE，dense FFN 承担稳定的"通用"计算。

注意力：局部/全局 5:1 交替

  • 周期性 5 层 local : 1 层 global。
  • Local = 滑动窗口 512 + RoPE（base freq 10,000）：只看近邻 512 token，负责局部细粒度。
  • Global = NoPE（无位置编码）：全序列可见但故意不加任何位置编码——这是长上下文外推不崩的关键，没有位置频率可外推就不会因超长序列而失稳。
  • GQA 8 KV head、head dim 128（推理 KV cache 小）；QK-RMSNorm 稳住注意力 logits 尺度；算核用 FlashAttention-4，序列维切分用 Ulysses 上下文并行。

归一化与初始化（稳住 78 层深网络的工程细节）

  • RMSNorm 同时放在 sub-layer 输入和输出、都在残差之前（Gemma 式 pre+post norm），残差流干净。
  • 无 bias、tied embeddings（输入输出词嵌入共享）。
  • Attention zero-init：把注意力输出的 RMSNorm gain 初始化为 0 → 训练初期每个残差块近似恒等映射，深网一开始就稳。
  • Tokenizer o200k_base，词表 200,019。
架构演化（Table 7，消融式长大）
从 v2（23B/600B，54 层，MoE 4/192）沿缩放梯子一路长到 v5 = MAI-Base-1（35B/1T，78 层，MoE 8/512）。每一代都在梯子上验证改动的效率增益，MFU 全程保持 >20%。

块 2 · 缩放与消融方法论（§2.2–2.3）—— 全篇"科学严谨"的落地

核心问题：架构/数据的每个改动，怎么判断是"真的好"还是"只在小模型上好"？答案是建一座 缩放梯子（scaling ladder）——训练一系列从小到大的模型（层数档位 L12→L78），看改动的收益是否随规模保持甚至放大。

三个关键量

  • TPP（tokens per active parameter）：每个激活参数分到多少训练 token，比"总 token 数"更本质，用来对齐不同规模的训练充分度。
  • 缩放律（Eq 1–2）：用小模型拟合 loss-算力幂律，外推大模型。

L = f(C) = A·C−α + E

C 是算力，E 是不可约损失（irreducible loss）。给定规模档位下数据量经验关系 D = L × 256 / 3。

效率增益 EG —— 本篇最该学的指标

把"loss 降了多少"这种不好横比的量，换算成统一的算力货币：

EG = f−1(L') / C'

读法：新方法在算力 C′ 下达到了 loss L′；用基线缩放律的反函数 f⁻¹(L′) 算出"基线要达到同样 loss 得花多少算力"，两者相除。EG>1 即比基线省算力（EG=1.5 ≈ 省 50% 算力）。

方法论结论
他们不看"单点上新方法 loss 更低"，而要求"新方法在整条梯子上 EG 稳定 >1"。只在小模型上好的 trick 会被这套筛掉——这是"避免捷径"的具体执行。

评测方法论：预训练阶段看 NLL/BPB，不看准确率

base model 没经后训练，直接测 accuracy 噪声大、受 prompt 格式影响；而 held-out 数据上的 NLL（下一 token 负对数似然）/ bits-per-byte（BPB）是连续、低噪声、可做细粒度梯子比较的信号，BPB 还能跨 tokenizer 可比。约 40 个 benchmark 分 5 大类，用一个加权目标聚合（Eq 3）：

Target = 0.5·Coding + 0.175·STEM + 0.175·Math + 0.1·General + 0.05·Multilingual

例 · 读权重就懂定位
Coding 独占 0.5 权重 → 这是一个"码力/STEM 推理优先"的模型，预训练所有数据与架构取舍都向这个加权目标看齐（下文数据配比里 Code 占 54.6% 正是呼应）。

块 3 · 数据：30T token 怎么洗出来 + 配比怎么选（§2.4–2.5, 附录 B）

数据来源全自建（web、GitHub 代码、书籍、论文、新闻、多语、领域材料），三条红线（原文）：

"We choose to not use any synthetic data generated by language models ... make an effort to avoid and remove AI-generated content ... decontaminate common machine learning databases from our training data."

去重三板斧（数据质量核心配方）

  • 精确去重：SHA-512 哈希。
  • MinHash LSH @ 0.8：文档级近重复（Jaccard 阈 0.8）。
  • 语义去重：用 Qwen3-Embedding-0.6B 的 1024 维嵌入做 cosine 相似去重（小嵌入模型作工具，不算蒸馏能力）。
  • 20-gram 模糊去重 @ 80%：段落级。
记忆感知的 epoch 封顶（memorization-aware capping）
高质量数据可多训几遍但最多 8 epoch封顶；并监控"模型是否开始死记硬背"动态决定重复几遍——重复过头会从"学习"退化成"记忆"反而有害。

GitHub 代码管线细节（附录 B，占预训练一半以上）

公开 GitHub 处理成三类打包序列：Files ≈1.26T、Commits ≈4.5T、PRs ≈1.19T token。工程细节值得记：

  • Files：按仓库深度优先遍历顺序拼接成仓库级序列；StarCoder2 式启发式过滤；剔除生成代码（_pb2.py、.d.ts）、二进制、超 30K 字符或超长行文件。
  • Commits：每仓最近 10K commit；修改文件的 commit 前状态作loss-masked 前缀，只训 commit patch（git-diff 或 search-replace 格式）。
  • PRs：含标题/正文/关联 issue/评论/review/前状态/有序 commit；按 SWE-bench Verified 去污染（移除基准用过的 PR）；超长前缀做随机行"前缀压缩"，压缩后仍超 256K 的丢弃。

数据配比的"秩非不变性"（rank non-invariance）—— 最反直觉的结论

核心消融结论
两个数据配方 A、B，在小模型上 A 更好，换到大模型上可能 B 反超——即配方的优劣排序会随规模翻转。所以不能在小模型上选好配方直接搬到大模型，必须在缩放梯子上验证"配比"本身，而不只验证架构。这是他们花大力气建梯子的第二个理由。

块 4 · 训练配方：三阶段 + 超参 + FP8 精度（§2.6）

三阶段（Table 6）—— "训练 LLM 全过程"的主干

阶段token上下文长度GPU 数LR
预训练30T16,3848,192 GB200warmup~12B 后 cosine 2e-4→2e-5

逻辑：先在 16K 短上下文吃完 30T 主料（短上下文 MFU 最高），再用 mid-training 分两步把上下文 16K→64K→256K，同时在 mid-training 里加重推理学科。mid-training 配比：STEM/math 35%、code 55%、background 10%——比预训练更聚焦，为 RL 打地基。

预训练超参（逐个记）

  • 优化器 AdamW：β1=0.95, β2=0.925（偏低，二阶矩反应快、适配大 batch）, ε=1e-8。
  • weight decay 0.1，分组：attention 0.01、embedding 0.005（嵌入几乎不衰减）。
  • grad clip 1.0；dropout 0.15（现在大模型少见还开）；全局 batch ≈134M token（8192×16384）。

FP8 混合精度训练（最硬核的工程细节）

  • 前向 GEMM 用 FP8 E4M3（4 位指数，前向够用）。
  • data-gradient 用 FP8 E5M2（反向梯度动态范围需求大，5 位指数）。
  • weight-gradient 用 BF16，累加用 FP32（精度敏感处不省）。
  • delayed scaling：用过去 1024 步的 amax 历史定 FP8 缩放因子，不每步现算。
  • stochastic rounding（随机舍入）：低精度累加按概率舍入，消除系统性偏差。
FP8 哲学一句话：算得多的地方（前向/反向 GEMM）用 FP8 省算力，精度攸关的地方（权重梯度、累加）保留高精度，分而治之。

块 5 · 长上下文扩展（附录 C）—— 消融最密集的一块

目标是 256K 上下文窗口。但全程用 256K 训练 MFU 太低不现实，于是采用分段策略：预训练 16K → mid-training 64K（Stage 1）→ 短的专门阶段扩到 256K（Stage 2）。整节都是支撑这个配方的消融。

三个评测设计（怎么量化"真用上了长上下文"）

  • Code NLL：把内部代码仓拉成 token 流，取 256K 块，固定末 16K 做 NLL，逐步增大前缀。理想长上下文模型应随前缀变长（更多同仓相关代码）而 NLL 单调下降。
  • Retrieval NLL：取 32K 文档拆成相关的 A(后)/B(前) 两块（B 对预测 A 有用），往中间不断塞无关内容把 A、B 推远到 256K，看模型能否"隔着噪声"仍用上 B。
  • Generative QA：问题放在上下文不同位置，测准确率随总长与证据位置的变化。
消融结论 1 · 长上下文数据配方：越简单越好
试过上采样长文档、调域配比等多种变体，没有一个带来有意义提升。最简单做法——沿用前一阶段 mid-training 的同一配比、按 256K 重打包——就很好，最终即采用它。原文："none of these modifications yielded meaningful improvements. The simplest approach ... works well."
消融结论 2 · 渐进式扩展 ≈ 全程长上下文 mid-training（省大钱）
对比五配置：16K/32K/64K/128K 各训 1T token 的 mid-training，以及"32K mid-training 1T + 约 100B token 扩到 256K"的渐进式。结果：渐进式 checkpoint 在 128K 上的 NLL 追平完整 1T-token 128K mid-training，而用的长上下文 token 少得多；且五配置在短上下文（16/32K）NLL 收敛到几乎一致 → 长上下文 mid-training 不损短上下文质量。结论原文："mid-train at a short, MFU-friendly context length and extend at the end."
消融结论 3 · 扩展适应极快
256K Code NLL 的改善绝大部分发生在前 1–10% 的训练迭代内，之后 plateau。说明扩展阶段不是在学新能力，只是把位置/注意力机制校准到没见过的序列长度——长上下文所需表征在预/mid-training 已具备。
例 · 外推能力与"末端劣势"
Generative QA 上观察到最多 4× 长度外推（32K 训练的模型能在 128K 上答对）。有意思的失败模式：超出训练分布后，模型对"末端（end-of-context）"位置的信息检索格外吃力，而非远端——因为评 64K 输入时前 32K 在训练分布内、末尾落在没训过的位置。长上下文训练消除了这种不对称。

最终配方（保守选择）

64K mid-training + 140B token 的 256K 扩展。作者坦言消融（基于 NLL）其实提示更短的 mid-training 长度和更短 token 预算就够，但"长上下文与后训练的交互刻画不足"，故选了更保守的方案。并预告：同一分段法可低成本直接把末段扩展目标换成 1M token。

块 6 · YOLO 训练框架与集群工程（§2.8, §6）

YOLO：自研分布式训练框架

  • 全套并行：ZeRO 1-3 + EP（专家并行，512 专家分散必需）+ TP + CP（配 Ulysses）+ PP。
  • bitwise determinism（逐比特确定性）：同输入同种子逐比特可复现——这是"爬山机器"可重复性的刚需，否则无法判断一个改动的收益是真的还是随机波动。
  • async checkpointing（存档不阻塞训练）+ fault tolerance（8192 卡上硬件故障是常态，自动检测/剔除坏节点/从 checkpoint 恢复）。

把 goodput 当头号 KPI（§6.2 工程结论）

定义 goodput = 理想训练时长 / 实际墙钟时长，并把差距分解到各开销类别。关键认知：一次故障不只花"重启前的时间"，还会强制从上个 durable checkpoint 重算、触发启动/调度延迟、扰动 placement、拉低恢复后 MFU；MFU 下降即使任务没崩也当"生产事故"处理，因为还在烧 GPU-hours 却产出更少进展。

MAI-Base-1 预训练 goodput 实测分解
8K GPU 上 goodput 达 90.0%（比早期更大的 run 还高），总开销降到 51 小时：其中重算仅 6.5h（15%）、非 stepping 时间 14h（27%）。最大剩余瓶颈变成 MFU drop：18h 占 35%，由 checkpointing、网络退化、内存压力、硬件健康切换驱动。——这是一条"先治可见故障、再治隐性 goodput 损失"的清晰演进。

集群与部署

  • MAI-Base-1 在单逻辑集群 8K GB200 预训练；MAI-Thinking-1 的 RL 爬坡用 4.6K GB300。主 run 刻意保持同代加速器、同构环境以降低实验方差。
  • 确定性被当作一等基础设施属性：须消除静默数据损坏、保持通信拓扑稳定、跨 checkpoint/restart 保持浮点归约与累加顺序。
  • 推理：在 Microsoft MAIA-200 上部署，同机架功耗预算下 token 生成吞吐比 GB200 部署高 40%+（performance-per-watt）。

块 7 · RL 配方（§3.1）—— 从零学推理、撑住数千步长爬

RL 爬坡从零开始，没有任何现成 reasoning trace 做冷启动。基座是 GRPO，但做了两处关键改造来保证"爬得久不塌"。

基座：GRPO（token 级策略梯度，Eq 5）

对一个 prompt 采 G 条回答，用组内相对好坏算优势（无需 critic）：优势 = (本条奖励 − 组均值)/组标准差，再用 PPO 式 clipped 目标最大化。

改造 1 · 自适应熵控制（Eq 7–8）—— 防熵塌陷

长 RL 最常见的死法是熵塌陷（模型过早变得确定、丧失探索）。他们不手调熵系数，而是用一个积分控制器动态调节 clip 上界 k，把策略熵稳在目标值 H*：

kt+1 = kt + δ·(Ht − H*)

熵低于目标 → 自动放宽 clip、鼓励探索；高于目标 → 收紧。实测系数：目标熵 H*=0.3、步长 δ=0.25、kmax=2.5、ε=0.6。

改造 2 · 外层比值裁剪（Eq 9）—— 防罕见大比值炸训练

在标准 PPO 内层 clip 之外再加一道外层比值上界 rmax（dual-clip 思路），丢弃重要性比值过大的样本：实测 rmax=50，rmin=0 不约束。off-policy 时偶发的巨大比值会被这道闸拦住，避免单个样本的梯度把训练带偏。

奖励设计（Eq 10–12）：任务对错不是全部

R = Rtask + wlang·Rlang − wlen·Rlen

  • Rtask：可验证奖励（数学/代码判对错、IF checker 等）。
  • Rlang：语言一致性奖励，防中英混杂等（wlang=0.5，每词惩罚 α=0.005）。
  • Rlen 长度惩罚（Eq 12）：Rlen = ρq·|yi|/ℓmax，按 ℓmax 归一 → 长度上限越大、有效惩罚越弱，鼓励长预算下探索更长 CoT。wlen=0.25，到 128k 阶段置 0。

采样与稳定性工程细节

  • 早退采样：先发 Gearly=16 条，pass-rate 落在 [0.05,0.8] 才继续发满 G=128 条；否则直接 abort 这道题——省掉太简单/太难题目的算力。满额过滤区间 [0.1,0.8]。
  • top-p mask replay：复用 rollout 采样时的 top-p 截断 mask，把被排除 token 的 logit 设 −∞ 后再 softmax，显著减少训练-推理的策略散度（代价是存/回放 mask）。p=0.97。
  • 长度扩展课程：rollout 上限从 8k 开始，按 2 的幂逐步升到 128k。低性能期很少需要长 CoT，先短后长大幅省推理成本。
  • off-policy 容忍：每 2 次推理权重更新间走 5 个梯度步；丢弃生成策略落后超 8 次推理更新（=40 梯度步）的 rollout。长序列（最难题）在异步栈里更"陈旧"，故 128k 时把 LR 从 1e-6 降到 9e-7 以降 off-policiness。

自蒸馏（§3.1.4）—— 让数千步长爬变得可行，本质是 SFT

注意：这里的 "self-distillation" 是 SFT，不是 OPD（token 级 on-policy 蒸馏）。原文："we collect rollouts generated during RL and perform SFT on a midtrained checkpoint using these rollouts." "self" 指数据来自自家模型/专家的 rollout，不是第三方。用途：切换到原生 chat 格式、从 run 崩溃中恢复（重置数值）、把进展迁移到新 base。

自蒸馏关键消融结论（best practices）
· O(1M) 条推理轨迹就够追上老师，再多边际递减且收窄分布、挤占后续 RL 的探索空间。
· 训"含错误最终答案的轨迹"与"只训成功轨迹"效果相近（但成功轨迹本来就远超 1M，故最终只用成功的）。
· 用后期多 checkpoint 的轨迹很重要：掺入很早的 checkpoint 轨迹会明显掉点；只用最终 checkpoint 的轨迹则恢复 RL 后更弱——多 checkpoint 提供多样性利于探索。
· 固定 token 预算下，增加 prompt 多样性 > 每 prompt 多采几条；简单随机采样优于最短轨迹采样等启发式筛选。
· 自蒸馏会让模型遗忘长上下文行为（尤其轨迹来自短长度的早期 RL），故长度扩展前把 mid-training 数据掺进自蒸馏数据。

自蒸馏 SFT 超参：packed、global batch 2048、序列 128k、AdamW wd 0.001、cosine LR 1.7e-5→5.2e-6、warmup 2%。（与 RL 爬坡的 constant 1e-6 完全分开列。）

块 9 · Rocket 异步 RL 基础设施（§3.6）

自研 Rocket 大规模异步分布式 RL 框架：learner 用 YOLO、推理用 SGLang，因为开源 RL 框架撑不住"数千 GPU 异步 RL"的规模。核心是单 controller + problem/rollout worker 池 + SGLang 推理池（含 router）。

  • Controller：装载 RL 任务发给 problem worker，收回带评分元数据的 rollout，过滤后成批发给 learner。大 run 主用 off-policy RL，on-policy 留给小实验/调试。
  • Problem Worker：按早退策略先发 16 条、通过再发 128 条，算归一化优势（可含长度惩罚/GRPO 归一），并实现大规模异步容错（rollout worker 挂了重试）。
  • Rollout Worker：生成单条 rollout——发 prompt 给推理服务器、解析响应、执行工具调用、把结果拼进下一轮，直到模型停止调工具或超步数/超时；完成后判题。
  • 权重传输 resharding：按 DP 组子集与不相交的推理副本切片并行传权重——"36 服务器四分，四路 9 服务器并行传输"，提升吞吐并收窄故障爆炸半径。
  • 数值 gap 缓解：训练-推理数值差异用 bf16 对齐，配合 §3.6.4 的稳定性改进，减少长 run 发散（否则就得靠自蒸馏重置）。

块 10 · 推理轨迹的演化（附录 D）—— "从零爬"才有的干净观察窗

因为不蒸馏任何第三方 CoT，他们得到一个干净视角：观察 RL 变强过程中 CoT 行为如何自发演化。这些是定性但很有洞察力的实验结论。

STEM：弱模型靠猜，强模型真算
以一道 AIME 2024 题（答案 240）为例，差别不在初始代数设置，而在最终验证步：强模型推出全部候选 k∈{8,32,200,512} 再按定义域 x>0 筛除 512；弱模型从可见根 18/72/98 猜最小值点，臆造出 40、152 等伪值，甚至算错和。强模型会逐个候选代回验证根是否为正、是否落在正确区间。
Agentic 行为 1：强模型写并跑单测，弱模型只做基本自检
agentic RL 训练中自发涌现的行为是反复跑 unit test 验证工作。弱模型只罗列"我实现了哪些需求、保持了向后兼容"（嘴上说 all requirements addressed），强模型则真的跑测试、确认 "tests still pass" 后再逐条核对需求。
Agentic 行为 2：强模型做"证据考古"，弱模型纠结编辑机制
强 checkpoint 的 CoT 在动手前先在仓库里找证据（被 revert 的 commit、payload、测试）；弱 CoT 认对了目标，却把后续回合耗在精确匹配 old_str、缩进 tab/空格、修复编辑损坏这类编辑工程上，视野狭窄、陷入 fixation。
Agentic 行为 3：强模型找"真源头"，弱模型在相邻路径臆测
强 CoT 把行为追溯到喂给生成的数据源头（source of truth）再推理；弱 CoT 表面理解了可见代码路径，却围着相邻的"生成代码路径"反复试错，最后留下边界 case 未处理。
方法论价值：这些 archetype 不是逸事——它们成了判断 checkpoint 强弱的可观测信号，也反向指导奖励与数据设计（例如显式奖励"跑测试""找源头"这类行为）。
