Capable yet Parsimonious：抽取并刻画前沿模型的"隐藏思维链"

用一个 API 工具调用的小技巧，把闭源前沿模型藏起来的中间推理"逼"出来，再横向比较它们怎么推理 · 精读研究报告

结论速览 TL;DR

一句话：闭源前沿模型把原生思维链 (CoT) 藏起来只给答案。作者发现注册一个"假"推理工具、并用 API 的 tool-choice 强制模型第一步必须调用它，就能把中间推理"逼"到工具参数里显形——这套 FORCED-REASONING 协议只依赖标准 API 接口。再用抽取到的 trace 横向比较 GPT-6 Astra / GPT-5.6 Sol / Claude Opus 4.8 / Sonnet 5，发现最强的 Astra 反而写得最短、最"密"、最直。

三大发现：① 高效推理 = 简洁+高信息密度+少分叉（Astra 的推理树最窄，中位节点数 27 vs Sonnet 的 136）；② 压缩过的 trace 迁移性不均——强模型能几乎无损复用，弱模型用不动；③ 一个能观测"隐藏推理"的验证过的工具，即便 provider 报告 0 推理 token 也能诱发出推理内容。

1 · 概览

研究问题闭源前沿模型只给答案、把原生 CoT 藏起来，形成"测量鸿沟"：benchmark 只告诉我们模型能不能解出，却看不到它怎么解、强模型和高效模型的推理差在哪。能否在只用标准 API 的前提下，把中间推理抽出来做跨模型比较？ 核心贡献① FORCED-REASONING：一个只靠标准 API tool-calling 就能诱发中间推理的协议；② 在开源模型上验证抽取 trace ≈ 原生 CoT（词汇+结构相似），使其可作代理；③ 用它沿"长度/密度、步骤类型、推理树、可迁移性"四个维度刻画前沿模型。 主要结论最高效的 GPT-6 Astra 写的 trace 最短、最不可压缩、最直（少分叉），但覆盖的推理"动作种类"和别的模型一样——它把初等步骤留在内部，只外化关键推理。且这种压缩 trace 弱模型复用不了。 适用边界需要支持"自定义工具 + 强制选定某工具"的 API-as-a-service 接口；不支持这些控制的端点用不了。闭源部分证据只能是行为层面——无法证明抽出来的就是模型真实的内部思维。

2 · 方法剖析：FORCED-REASONING 协议

核心机制：把推理"骗"进工具参数

整套方法只用一个标准 API 特性——函数/工具调用。步骤是：

  • 注册一个"推理工具"：它只有一个自由文本字符串参数，专门用来装中间推理；这个工具不做任何真实计算，唯一作用是让中间文本显形并留在对话里。
  • 第一步用 tool_choice 强制模型必须调用它（named tool choice），同时关闭原生 reasoning。这是"forced"的唯一含义——只强制"第一次的工具选择"。
  • 记录该工具调用的参数（=抽取到的推理），把这次 assistant 工具调用 + 一个空的确认回执追加回对话，然后恢复自动工具选择。
  • 模型据此继续：可以再次调用推理工具，也可以直接给出最终答案，直到答完为止。

关键洞察（承接前作 Ma 2025 / Wang 2025）：推理行为和它"该在的输出通道"并不是绑死的。即便原生 thinking 被禁用、provider 报告 0 推理 token，模型仍会在别的字段（这里是工具参数）里吐出推理内容。所以这既是"抽取工具"，也是一个揭示"现有 reasoning 开关挡不住推理外泄"的探针。

直觉类比 · 举例理解
想象老师禁止你在"草稿纸"（原生 CoT 通道）上写字，但桌上有个"便利贴"工具，规则是你必须先在便利贴上写一句再说话。你自然会把演算写在便利贴上——研究者读便利贴，就等于读到了本该藏起来的草稿。工具本身不算数（不做计算），"强制先写便利贴"这个动作才是撬点。

为什么可信：先在开源模型上对照

抽出来的文本会不会只是事后编的合理化说辞（post-hoc rationalization）而非真推理？作者先在能看到原生 CoT 的开源模型（DeepSeek-V4-Flash、GLM-5.2）上验证：FORCED-REASONING 抽取的 trace 能恢复接近原生的任务表现，且与原生 CoT 有显著的词汇重合与结构相似。这才支撑"把抽取 trace 当原生推理的行为代理"用到闭源模型上。

刻画维度 · 怎么量化"推理长什么样"
作者从"整条 trace → 单个步骤"分四个维度量化：①长度与压缩率——用 zlib 无损压缩比当冗余度的粗测，zlib ratio 越高 = 越难压 = 重复/套路越少；②推理动作分布——套用 Schoenfeld 情节理论的 7 类：READ / ANALYZE / PLAN / IMPLEMENT / EXPLORE / VERIFY / MONITOR；③局部粒度——同一步骤各模型写得多详细；④推理树——用 LCoT2Tree 把 trace 转成树，量 width p(最大横向展开)、depth q(最远步)、N(节点数)。

3 · 实验与结果

实验设置

基准MATH（80 道 HMMT + APEX Shortlist 竞赛题）、LiveCodeBench(LCB, 100 题子集)、Humanity's Last Exam(HLE, 100 题子集)，覆盖数学/代码/多学科。 三种条件None（禁用原生推理、无工具）· Native（开高强度原生推理）· Forced（本文协议）。全部经 OpenRouter 调用。 模型闭源：GPT-6 Astra、GPT-5.6 Sol、Claude Opus 4.8、Sonnet 5；开源验证：DeepSeek-V4-Flash、GLM-5.2。（Astra 不支持关原生推理，故用最低推理强度、无 None 列。）

发现二：局部粒度——Astra 省略"人人都会"的步骤

同一道题、同一个推理步骤，各模型写得详略不同。两个规律：算术/代数展开被压成更少的书面步骤；背景知识直接用、不复述。

数字举例 · HLE-075 化学题的"价电子求和"（原文 Table 2）
要构造 C₁₂H₁₈O₆、算价电子总数：
· Astra 直接写：48 + 18 + 36 = 102——不复述"C 贡献 4、H 贡献 1、O 贡献 6"。
· Sol / Opus 则先摊开：C:12×4=48, H:18×1=18, O:6×6=36 → 102。
同理算术验证 420261 / 101：Astra 一句 101×4161=420261, yes；Opus 会拆成 101×4000=404000, 101×161=16261, 合=420261。覆盖同样的检查，Astra 用更少的显式步骤。这与 OpenAI 系统卡对 Astra"降低了verbalize推理的倾向与必要性"的描述一致。

发现四：压缩 trace 的迁移性不均 → 对蒸馏的启示

对蒸馏/OPD 的核心启示：trace 作为监督信号的价值不是绝对的，而是相对于"读它的学生"。这给蒸馏里的"容量鸿沟"（更强的教师不一定教出更好的学生）提供了一个机制假说——最强的教师写的 trace 最压缩，恰好省掉了弱学生自己补不出来的那些步骤。可检验的预测：把压缩 trace 展开成隐含中间步，应能恢复它对弱学生的大部分价值，而几乎不影响强学生。（注：作者只测了 in-context 复用，未直接做 fine-tuning 蒸馏。）

4 · 相关工作与定位

本文处在"隐藏 CoT 抽取"+"CoT 结构/效率分析"两条线的交叉点。

隐藏 CoT 抽取：Panfilov 2026 靠跨会话/跨模型重放 provider 返回的加密推理块；Trace Inversion (Zhang 2026a) 从可观测输出事后重建 trace；REP (Lu 2026) 用 shadow-model 示范诱导模型在可见响应里外化推理；EchoCoT (Qu 2026) 已经把 REP 的思路扩展到 API tool-calling 场景，加一个攻击者定义的 scratchpad 工具反复归档/重放原生推理。本文的 FORCED-REASONING 与 EchoCoT 最接近——都走工具通道，差异在于用 tool-choice 强制首次选定 + 关原生推理的极简协议。

推理外泄于"指定通道"之外：Ma 2025（用 response prefilling 绕过 thinking block）、Wang 2025（no-think 模式仍会外化推理）——这两条正是本文的动机来源。

CoT 结构分析：本文直接复用 Li 2025 的 Schoenfeld 情节理论（7 类推理动作）、LCoT2Tree (Jiang 2025，转推理树)、TRACE (Zhang 2026b)。真正的差异化不在"抽取手法"，而在把抽取 trace 当成"观测仪器"去横向刻画前沿闭源模型的推理效率与结构——这是以往工作没系统做过的。

6 · 水分与价值：批判性判断

实打实的贡献

  • 把"抽取 trace"变成一台观测仪器。以往同类工作止步于"能不能把隐藏推理弄出来"；本文真正的差异化是拿抽出来的 trace 去横向刻画前沿闭源模型的推理效率与结构（长度/密度、步骤类型、推理树、可迁移性四维），这是 benchmark 分数给不了的行为视角。
  • 先在开源模型上做了对照验证。用能看到原生 CoT 的 DeepSeek-V4-Flash / GLM-5.2 证明抽取 trace 与原生 CoT 有词汇+结构相似、且能恢复任务表现，才敢把它当闭源模型的行为代理——这一步让结论不至于悬空。
  • 对蒸馏/OPD 给了可检验的机制假说。"最强教师写的 trace 最压缩，恰好省掉弱学生补不出的步骤"为"容量鸿沟"提供了一个能证伪的预测（展开压缩 trace 应能恢复它对弱学生的价值），对做在线策略蒸馏的人尤其有参考价值。
  • 伦理处理规范。代码走负责任披露、私下交给 OpenAI/Anthropic 安全团队，而非直接放出一个"绕过 reasoning 开关"的探针。

水分需谨慎处

  • 抽取手法相对前作增量有限。EchoCoT (Qu 2026) 已把 REP 思路搬到 API tool-calling 场景；FORCED-REASONING 的新意主要在"tool-choice 强制首次选定 + 关原生推理"的极简化，属于工程化收窄而非范式突破。
  • "隐藏 CoT"措辞略夸大。无法证明抽出来的就是模型真实的内部思维；作者自己也承认可能存在事后合理化。严格说这是"被诱发的、行为上等效的推理"，不等于"读到了模型藏起来的那份草稿"。
  • 样本量偏小。MATH 80 题、LCB/HLE 各 100 题子集；跨模型结构差异（如 Astra N=27 vs Sonnet 136）虽显著，但置信区间与题目选择敏感性讨论不足。
  • 强依赖会漂移的闭源模型 + 无公开代码/数据。确切数字是时间快照，GPT-6 Astra 一旦下线/更新即无法精确复现；抽取 trace 也未随文发布。
  • 迁移性只测了 in-context 复用，未真正做 fine-tuning 蒸馏。对蒸馏的"启示"仍是外推，核心假说尚未在真实蒸馏 setting 上验证。
