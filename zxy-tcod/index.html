TCOD 精读：多轮智能体的时序课程在线蒸馏
Exploring Temporal Curriculum in On-Policy Distillation for Multi-turn Autonomous Agents

作者 Jiaqi Wang†, Wenhao Zhang, Weijie Shi, Yaliang Li, James Cheng† · Tongyi Lab, Alibaba（†CUHK） |  arXiv 2604.24005v3（2026-04-29） |  代码 kokolerk/TCOD（基于 Trinity-RFT） |  作者踩坑博客 on-policy distillation pitfalls

这是一篇"方法简单、问题真实"的工程论文：它指出 vanilla 在线蒸馏（OPD）用在多轮 agent 上会轨迹级 KL 失稳（KL 随 turn 累积爆炸、成功率塌到 0），再用一个"按 turn 数做课程"的小改动（F2B / B2F）把它救回来。但这篇报告的真正重点在后半段——结合作者本人在 9 个 closed issue 里的逐条确认，论文的超参表、术语、评测协议存在多处与开源代码不一致的硬伤，直接决定你能不能复现。

0 · 一句话结论与水分评分

方法贡献（真实）：把"课程学习"从"按样本难度"换成按轨迹 turn 深度，纯用学生自采数据、不需要外部难度模型。F2B 限制最大交互步数 k 由小到大；B2F 让教师先走成功轨迹前缀、学生从中途接管、再逐步撤掉教师前缀。两者都只需"几行代码"的改动。

效果（论文自报）：把 Qwen3-1.7B 从近 0 成功率救回到 ~18 avg；Qwen2.5-7B 学生在 ALFWorld 比 OPD 最高 +15.71 SR；平均少 2.97 action 步；ALFWorld hard split 上 B2F 比"连 pass@10 都做不到"的教师还高 ~14 分（超越教师能力边界）；训练时间比 OPD 少 ~32%；对课程增速 η∈{2,4,6} 不敏感（<2% 波动）。

⚠️ 但：论文可信度被超参表拖累

作者在 issue #6 亲口承认 Table 4 的若干内容是"让 claude code 根据代码帮我 vibe paper"、未逐条核对，导致 Data type 写成 BF16（实际应为 FP32） 等硬伤。附录超参表是复现的唯一依据，错一个精度就从"复现成功"（64.3%）变成"复现失败"（39.6%）。好在作者态度极好，逐条确认并承诺改 arXiv。

水分 4/10（方法真实有效、代码开源、作者极度配合；扣分在超参表/术语/评测协议与代码多处不一致，需要靠 issue 才能对齐）  ·  复现价值 8/10（想复现多轮 agent OPD / Trinity-RFT 的人，这篇 + 它的 issue 区几乎是一份现成的避坑手册）

1 · 核心问题：轨迹级 KL 失稳（Trajectory-Level KL Instability）

设 agent 状态为完整交互历史 h_t=(o₀,a₀,…,o_t)，vanilla OPD 的目标是在学生自己的状态分布下，逐 turn 最小化教师-学生的 KL：

L_OPD(θ) = Eτ∼πθ [ Σt=0…T−1 DKL( πϕ(at|ht) ‖ πθ(at|ht) ) ]　（式2）

三个实证观察（pilot study on ALFWorld）

  • 观察 1：KL 升高与成功率塌缩同时发生。小学生（Qwen3-0.6/1.7B）配强教师（Qwen3-30B-A3B-Instruct）时，KL 快速escalate、SR 塌到近 0——与单轮（数学/QA）里 KL 稳定下降完全相反。
  • 观察 2：即便 KL 最终收敛，初始值高达 ~1000+（Qwen2.5-3B←7B 初始 1223→末 97；7B←7B 359→62），比收敛值高一个数量级。
  • 根因：compounding error amplification over the trajectory——学生生成的 action/observation 被追加进 h_t，turn 之间产生因果耦合，KL 随 turn 单调增（Fig 2d）。对小模型是灾难性的，对大模型"能扛但极低效"。

对应原文 §4.1、Appendix B（Fig 7/8）。注意：论文正文此处用 rollout/env_done/mean 作为"success rate"的度量——这正是后面 issue #8 要讨论的术语口径问题。

2 · 方法：TCOD-F2B / B2F

F2B：Forward-to-Backward（浅→深）

学生最多 rollout k 步，k 随训练步线性增长，只在前 k 个 turn 上算 KL：

LF2B(θ)=Eτ∼πθ[ Σt=0…k−1 DKL(πϕ‖πθ) ]，　k = kstart + ⌊n/η⌋　（式3、式4）

n=当前训练步，N=总步数，kstart=初始步数，η=课程增速。论文固定 kstart=1, η=2，并在 §5.4 扫 η∈{2,4,6}。优点：不需要任何演示数据，drop-in。

B2F：Backward-to-Forward（教师导航）

先用教师 pass@10 采集成功轨迹 τ*（长度 L）；每步让教师 stop-gradient 执行前 L−k 步把学生放到"成功门口"，学生接管后 k 步并只在这 k 步算 KL：

LB2F(θ)=Eτ∼(πϕ,πθ)[ Σt=L−k+1…T−1 DKL(πϕ‖πθ) ]，　k=min(kstart+⌊n/η⌋, L)　（式5）

train-test mismatch 处理：教师前缀从 L−1 步逐渐减到 0，训练结束时学生全程自走，使训练/测试分布对齐（Appendix D.5 验证端到端 SR 随训练稳步上升）。代价：B2F 需要预采成功轨迹（额外开销），且中途接管仍会多走探索步，所以 F2B 比 B2F 更省时（Fig 6）。

异步训练细节（§4.3，复现关键）

8×H20(96GB)：4×H20 actor rollout2×H20 learner 训练2×H20 teacher 推理，lock-free ring buffer。子轨迹经验回放：把长度 n 的轨迹拆成 n 个前缀 τ1:t 各存为独立 experience（故每 turn 是独立样本，教师在相同 token 序列上重算 logprob→无偏——这是 issue #8 说"训练时 memory 累积是有意为之、不是 bug"的原因）；staleness filter 丢弃 ncurrent−nold>Δmax，Δmax=2。

6 · ★论文不准确之处 + 应如何修正 + 为什么 + 证据

下面每一条都来自 kokolerk/TCOD 的 9 个 closed issue，由作者本人逐条确认。按"严重度"排序。

① 【最严重】Table 4 "Data type = BF16" 错误，应改为 FP32  issue #6

原文：Table 4 训练超参 Data type = BFloat16。

应修正为：Data type = FP32（float32）。

为什么要这么改：Trinity-RFT 的默认训练精度就是 FP32；BF16 会导致 OPD 的 train-inference / inference-inference logprob 失配——teacher 与 student 在同一 token 序列上算出的 logprob 因低精度产生系统性偏差，蒸馏信号被污染，训练直接崩。

证据（可量化）：复现者 Jacky-ustc 在 8×A100 上实测——FP32 step250 → ALFWorld 加权 overall 64.30%（与教师 63.29% 吻合，复现成功）；BF16 → 塌到 39.62%（复现失败）。并用 Codex 核对 Trinity-RFT 源码确认默认 FP32。

作者原话："非常非常抱歉由于我的失误，造成了 paper 的不准确……我马上就会修改提交一版本新的 arxiv！"；并承认附录超参表是 "让 claude code 根据代码帮我 vibe paper" 未逐条核对。

→ 复现任何一张表之前，先把精度改成 FP32。这是能否复现的第一道闸门。

② env_done 与 success rate 术语混用  issue #8

原文：正文与 Table 2/3 都说报告的是 "success rate (SR)"，图里却用 rollout/env_done/mean。

应修正为：明确区分——论文的 "SR" 实为 env_done（任务是否终止/完成的二值量）；而社区（如 GiGPO）惯例 SR = env_done && final_reward==1。

为什么：两者口径不同会让复现者对不上数——若你按 GiGPO 口径算 SR，会系统性低于论文；按 env_done 算才能对齐。

作者原话："在这篇 paper 里面，我把 env_done 和 success rate 当成一个意思了"（env_done=1 即视为任务完成）。复现者实测 env_done ≈ 论文报告的 SR。

→ 复现时统一用 env_done 口径，否则数字对不齐不代表没复现成功。

③ Table 5 max tokens 与 tcod_b2f.yaml 不一致  issue #9

原文：Table 5 评测 Maximum tokens = 4096；但开源的 tcod_b2f.yaml 把 max_response_tokens 设为 512。

澄清/修正：训练用 512（Table 4）、评测用 4096（Table 5），作者说对这些任务 512 其实已经够；yaml 需与 Table 5 对齐或在复现说明里标注。这不是硬伤，但会让人误以为配置错了。

→ 复现评测时按 Table 5 用 4096 更稳妥（长轨迹不被截断）。

④ ScienceWorld prompt 模板缺角色/系统描述  issue #8

原文：ALFWorld 模板开头有 "You are an expert agent operating in the ALFRED Embodied Environment"，而 ScienceWorld 模板（附录 E.2）缺少对应的角色/系统描述句，直接从 "Your ScienceWorld task is:" 开始。

应修正为：补齐 ScienceWorld 的角色描述，保持与 ALFWorld/WebShop 一致。为什么：缺少系统角色会影响小模型的 instruction following，是 ScienceWorld 分数偏低/不稳的潜在因素之一。

作者确认是疏漏，"后续补上"。

7 · 能复现哪几张表 + 逐表复现细节坑

7.1 先修两个会让结果直接作废的代码 bug

Bug A · ScienceWorld 1162-action 爆 prompt（已修，commit 17a8af2） issue #8

旧代码 _get_admissible_commands 用 info['valid'] = get_valid_action_object_combinations()，约 1162 个动作组合 → ~12,358 tokens/step（占 prompt 97%） → 超过 max_prompt_tokens=10240 → 100% 截断 → 所有回复变成 "focus"、parse_ok 0/30。

7.3 Table 3 ALFWorld 教师 39.57 这个数——最大的复现陷阱  issue #9

复现者在 valid_seen 全部 140 episode 上复现 Qwen3-30B 教师 SR，得到两套差 10+ 分的结果：

截断策略复现 SR与论文 39.57 对比
策略 A：滑窗，丢最旧的 (obs,action)，prompt 自包含37.86%接近 ✓
策略 B：开源代码 _handle_prompt_truncation（>10240 直接 dummy-skip 整条）27.14%低 10+ 分 ✗

根因：开源 _run_episode 把完整 memory 累积进 prompt，到 step ~16–18 就超 10240 → 触发 dummy episode 死亡 → SR 虚低。作者澄清：Table 3 评测用的是每步 bounded prompt——自包含的 ALFWORLD_TEMPLATE + 只保留 HISTORY_LENGTH=2 的最近 (obs,action) 对（对应 Table 5 的 History length=2 steps），不是开源代码里那套累积 memory。

关键区分：训练 vs 评测的 memory 处理不一样

训练每 turn 是独立 Experience、教师在相同 token 上重算 logprob（无偏），所以训练 rollout 里 memory 累积是有意为之、不是 bug；staleness 由 max_staleness=2 控制。评测则必须用 bounded per-step prompt + history=2，否则复现不出 Table 3。两者别混。

7.4 其余逐实验复现细节坑

模型版本（别选错） issue #4 / #9

  • Table 2 教师 = Qwen2.5-7B-Instruct + GRPO on ALFWorld；学生 = Qwen2.5-3B / 7B-Instruct（不是 base）。
  • Table 3 教师 = Qwen3-30B-A3B-Instruct-2507；学生 = Qwen3-1.7B / 4B plain（无后缀；Qwen3-1.7B 没有 Instruct-2507 变体）。
  • 无 SFT 预热，直接 OPD。Instruct 模型用 non-think 模式（开 thinking 会吐超量 token、撑爆 response）。

Table 2 教师 ckpt 不可得 → 用替代 issue #2

GRPO-Qwen2.5-7B 教师未发布（作者离职）。替代：HF kolerk/tcod collection，或社区 GiGPO-Qwen2.5-7B-Instruct-ALFWorld。用替代教师复现 Table 2 的绝对数字会有偏差，但 TCOD vs OPD 的相对趋势应保留。

教师 SR 方差大 issue #5

论文教师 85.71 vs 复现 83.57 / 92.5——测试集仅 ~130 任务，pass@1 方差大。建议：推理 temp=0.4 / 训练 temp=1.0、固定 seed=42、max_env_steps=30，多跑几个 seed 取平均再比。
