表格 AI Agent 的 Harness / Skill / 评估方法调研

面向 某表格 Agent 产品 线上 query 自动化评估与「表格大数据处理」方向的可复现深度调研 查阅日期：2026-10-15 · 工具：WebSearch 发现 + curl 取证（WebFetch 在本环境被域名校验拦截，未使用） 取证原则：每条结论附【来源 + 链接 + 逐字原文】；原文均 curl 实抓，不可核验处标「原文片段不完整」，不编造链接与原文。

一、执行摘要

表格 Agent 领域在 2025–2026 出现三条清晰的技术收敛线：

  1. Harness 从「让 LLM 写通用 Python」转向「把电子表格语义封装成专用工具」。 最先进的 Spreadsheet-RL 用 find_cells / inspect_range / fill_formula / recalculate_and_read 等电子表格原生动作替代裸 Python，并强制 inspect→modify→verify 的闭环；SheetCopilot 的「atomic action 虚拟 API」、SheetMind 的 BNF 文法约束命令都是同一思路——用受约束的结构化动作换取可验证性。工具调用协议则三分天下：MCP（sv-excel-agent）、Office.js（PISTA、Claude for Excel 生产版）、Python sandbox（SheetAgent、Eino）。

  2. Skill 已经标准化为单一格式：SKILL.md（YAML frontmatter + Markdown 正文）。 Anthropic 定义、发布在 agentskills.io，微软 Copilot in Excel 与开源 pi-for-excel 逐字采用（"must follow the industry standard format"）。分歧只在作用域与 IO：Anthropic xlsx 是「文件进文件出」的产出型 skill（并用 recalc.py 的 JSON 状态做公式零错误契约），微软/pi 是操作活动工作簿的「应用内」skill（@mention 触发、session/workbook 作用域）。

  3. 评估分三大流派：（a）执行 + 单元格比对 / online-judge（SpreadsheetBench v1、SB2 非可视化、WTM-BENCH 公式结果）——可复现、靠公式等价做容差；（b）加权结构匹配非单元格产物（WTM-BENCH 对图表/透视表/条件格式用 Jaccard 给部分分）；（c）LLM/VLM-as-judge + rubric（SB2 可视化用 GLM-4.6V 二值判定；WorkstreamBench 整簿用经校验的 agentic judge，0.90 准确率）。多模态（图表）是最大分水岭：SB2 用 VLM 判、WTM-BENCH 刻意不用 VLM 改走结构匹配。

对 某表格 Agent 产品 的核心启示：线上 query 评估应双档拆分——可判定档复用 SB2/WTM 的「锚点单元格 + 公式等价容差」做确定性自动判分，开放档复用 WorkstreamBench 式「经人工标注校准的 rubric + LLM-judge」，并像 SB2 一样把图表单独走 VLM-judge。详见第八节。

三、Harness 调研（最佳实践）

一般流程：用户 instruction → agent 在多轮循环中「观察表格状态 → 选工具 → 执行动作 → 校验」→ 产出工作簿。各家差异在动作空间粒度、工具调用协议、沙箱（真 Excel vs LibreOffice vs Python）、以及自校验机制四处。

3.1 Spreadsheet-RL（最先进，RL 训练 + 专用 harness）

来源：Spreadsheet-RL: Advancing LLM Agents on Realistic Spreadsheet Tasks via RL，Chi et al.（UIUC），arXiv:2605.22642v1，2026-05-21 链接：https://arxiv.org/html/2605.22642 原文（harness）："the harness defines a clear role for the agent, routes different spreadsheet operations to specialized tools, and enforces safe tool-calling rules that allow parallel read-only inspection while serializing write operations to avoid conflicting workbook mutations. The harness further guides the agent through an inspect, modify, and verify workflow" 原文（工具路由）："Use find_cells for headers/anchors, inspect_range for relevant ranges, fill_formula for formula-filled targets, clear_range for blank cells, delete_rows/delete_columns for structural deletion, recalculate_and_read after custom formula edits, and code_interpreter for custom logic or fallback." 原文（运行时）："Spreadsheet Gym utilizes Microsoft Excel as its spreadsheet instance... including dynamic array formulas such as FILTER, UNIQUE, SORT, TAKE, and MAP, many of which are lacking in alternative engines such as LibreOffice Calc."

  • 动作空间：电子表格原生工具（定位/读取/填公式/清空/删行列/重算读回）+ code_interpreter 兜底，把表格语义编进工具而非裸 Python。
  • 工具协议/并发：结构化 function-calling；"Concurrent read-only calls are allowed up to 20 per assistant turn. Write-related calls must be issued one at a time"——读可并行、写必串行。
  • 沙箱/校验：真实 Microsoft Excel 实例（Spreadsheet Gym），每条 rollout 文件系统隔离以支持并行 RL（VeRL + GRPO 结果奖励）；校验靠 recalculate_and_read「recalculates the workbook in Excel and reads requested ranges... allowing the model to verify custom formula edits under faithful spreadsheet semantics」。
  • 注：HF 模型卡 Spreadsheet-RL/Spreadsheet-RL-8B curl 无法渲染，仅得 WebSearch 片段，标原文片段不完整。

3.2 sv-excel-agent（MCP 协议代表）

来源：Open Source Excel AI Agent，SylvianAI（GitHub README） 链接：https://github.com/sylvianai/sv-excel-agent 原文："This repo consists of two main parts: an Excel MCP server (excel_mcp) and an Excel AI Agent Runner (excel_agent)... The Excel MCP server allows all agents to have access to a set of ~30 tools that allow editing of the Excel file directly."

  • 协议：MCP over SSE（mcp.run_sse_async(host="127.0.0.1", port=8765)，agent 连 http://127.0.0.1:8765/sse），工具协议与模型解耦——任何支持 MCP 的 agent 都能接。
  • 沙箱/校验：编辑输入文件的副本；在「SpreadsheetBench 的 50 条验证子集」上报 Pass@1；README 未明确自校验机制。

3.3 PISTA（Microsoft，Office.js + 可审计人机协作）

来源：Auditing and Controlling AI Agent Actions in Spreadsheets，Microsoft Research，arXiv:2604.20070 链接：https://arxiv.org/html/2604.20070 原文："Pista is implemented as an extension for Microsoft Excel that works on both the web and desktop versions... Snippets are transmitted to the front-end and executed via the Office.js API, with sheet state cached in the browser at each step to support Branching Exploration. We used Gemini 3.0 Flash for all features requiring code generation"

  • 协议/沙箱：LLM 生成 Office.js 代码片段在 Excel 前端（web+desktop）执行；每步缓存浏览器内表格状态。
  • 多轮/校验：人在环——「pauses at each step and advances only when the user clicks forward」，支持逐步局部纠错（Localized Editing）与分支探索（Branching Exploration）。校验是混合主动的人工监督，而非自动自检。

3.4 SheetMind（BNF 文法约束动作）

来源：SheetMind: An End-to-End LLM-Powered Multi-Agent Framework for Spreadsheet Automation，Cornell/HKUST(GZ)，arXiv:2506.12339v2，2026-07-13 链接：https://arxiv.org/html/2506.12339v2 原文："a hierarchical agentic system consisting of three specialized agents: Manager Agent that decomposes complex user instructions into subtasks; an Action Agent that translates these into structured commands using a Backus–Naur Form (BNF) grammar; and a Reflection Agent that validates alignment between generated actions and the user's original intent... the front-end executes them via Google Apps Script"

  • 动作空间：Action Agent 输出 BNF 文法约束的结构化命令（非自由 Python），作为 Google Workspace 扩展经 Apps Script 执行。
  • 校验：Reflection Agent 迭代校验（如复利公式历经 4 轮修正）；SCB-221 上报 100% Exec@1 / 54.8% Pass@1（优于 SheetCopilot 44.3%）。

3.5 其余经核验来源（并列第 5–7 来源）

  • SheetCopilot（arXiv:2305.19308，NeurIPS 2023）：原文："we propose to model the functionalities of existing spreadsheet software as a set of virtual APIs called atomic actions. An atomic action is comprised of an API name, a typed argument list, a usage document string, and several usage examples." → 平台无关的「原子动作虚拟 API」+ 状态机 Planning/Revising/Acting，出错回到 Revising 重提示直到输出 "Done!"。
  • SheetAgent（arXiv:2403.03636v2）：原文："It can invoke Python tool to interact with a Python sandbox for solution evaluation... utilizing libraries like openpyxl and pandas." → Planner/Informer/Retriever，Python sandbox（openpyxl/pandas）ReAct；自承不支持透视表/宏。
  • Eino ADK Excel Agent（ByteDance/CloudWeGo）：链接 https://www.cloudwego.io/docs/eino/overview/eino_adk_excel_agent/ 原文："Planner... Executor... CodeAgent: Receives instructions from the Executor, calls various tools (such as reading/writing files, running Python code, etc.)..." → 分层多 agent + plan-execute-reflect 闭环 + Ark Agentkit Sandbox。
  • Claude for Excel（demo）：anthropics/claude-agent-sdk-demos，原文："A demonstration desktop application powered by Claude and the Claude Agent SDK... LibreOffice (optional, for formula recalculation)" → Agent SDK 驱动 Python(openpyxl)，LibreOffice 做公式重算。生产版（Office.js 侧栏 + Opus 4.6）页面为营销内容，标原文片段不完整。

负结果：MiningLamp/明略「Octo」GitHub 组织是人机协作工作台（octo-server/cli/matter），非表格 harness；Google Workspace 的「Octo – AI Data Analyst for Google Sheets」marketplace 页 curl 无法渲染，标原文片段不完整。

四、Skill 调研（最佳实践）

一般流程/IO：skill = 一个文件夹，内含 SKILL.md（YAML frontmatter 的 name/description 供模型判断何时触发，Markdown 正文是指令逻辑），可选 scripts/references/assets。模型按 description 动态加载。输入输出要么是文件（.xlsx/.csv，产出型），要么是对活动工作簿的操作（应用内型）。

4.1 Anthropic xlsx skill（格式定义者 + 产出型）

来源：skills/xlsx/SKILL.md + repo README，Anthropic（anthropics/skills） 链接：https://github.com/anthropics/skills/blob/main/skills/xlsx/SKILL.md 原文（frontmatter）："description: \"Use this skill any time a spreadsheet file is the primary input or output. This means any task where the user wants to: open, read, edit, or fix an existing .xlsx, .xlsm, .xltx, .csv, or .tsv file ... Do NOT trigger when the primary deliverable is a Word document, HTML report, standalone Python script...\"" 原文（README）："Skills are folders of instructions, scripts, and resources that Claude loads dynamically... Each skill is self-contained in its own folder with a SKILL.md file containing the instructions and metadata that Claude uses."

  • 作用域/触发：模型按 description 触发，含显式反向触发（Word/HTML/Google Sheets 不触发），精确边界避免误召。
  • IO/schema：消费/产出 .xlsx/.xlsm/.xltx/.csv/.tsv；无 JSON 输出 schema，但有硬性产出契约："Use formulas, never hardcoded results." 与 "Zero formula errors. Never ship while recalc.py reports errors_found." —— recalc.py 返回 JSON 状态包（status∈success/errors_found、total_formulas、total_errors）。这是全场唯一的机器可读输出 schema，对自动化评估极有价值。

4.2 pi-for-excel（agentskills.io 标准 + 作用域语义最清晰）

来源：README + docs/agent-skills-interop.md，tmustier（开源多模型 Excel 插件） 链接：https://github.com/tmustier/pi-for-excel/blob/main/docs/agent-skills-interop.md 原文："## 1) Agent Skills (standard) — Standard: https://agentskills.io/specification — Format: SKILL.md + frontmatter — Portable across providers/harnesses ... Use the term skill only for standards-based SKILL.md artifacts."

  • 作用域/调用：运行时暴露 skills 工具（list/read/install），系统提示注入 <available_skills> 让模型按需加载；读结果按 session 缓存，session 身份变化即失效。integration 另带 scope (session/workbook)。
  • 复用/组合优先级："1. bundled 2. managed external (skills/external/...) 3. workspace auto-discovered"；并警示 "workspace-provided skills are untrusted input and may contain risky instructions/scripts"——供应链/注入风险提示。
  • IO：16 个内置工具操作活动工作簿（如 write_cells「with overwrite protection and auto-verification」）；skill 本身「mostly instruction logic」无正式输出 schema。

4.3 Microsoft Copilot in Excel — Skills（标准被官方采纳）

来源：Use skills with Copilot in Excel / Custom skills format requirements，Microsoft Support 链接：https://support.microsoft.com/en-us/excel/copilot/copilot-in-excel-skills 原文："Custom skills must follow the industry standard format to be recognized by Copilot in Excel. Each skill needs an individual folder, and that folder must have a SKILL.md file... The metadata section... is called the frontmatter. It holds the name and a description that tells Copilot when to use the skill."

  • 作用域/调用：@mention（如 @clean-data、@chart-design、@skill-builder）；自定义 skill 存 OneDrive，文件夹名必须等于 SKILL.md 的 name 才被识别（改名即「卸载」）。
  • 意义：微软在生产级产品里逐字采用 Anthropic 的 SKILL.md 约定，坐实该格式为事实标准。

4.4 octospec-workflow（明略 octo-spec，SKILL.md 封装范例，非表格）

来源：.claude/skills/octospec-workflow/SKILL.md，Mininglamp-OSS/octo-spec 链接：https://github.com/Mininglamp-OSS/octo-spec/blob/main/templates/octospec-init/.claude/skills/octospec-workflow/SKILL.md 原文："description: Use when implementing a feature, fixing a bug... Drives the octospec 4-phase engineering flow (Plan, Implement, Verify, Finish)... Triggers on requests like \"add ...\", ... 写功能, 修 bug..." - 标准 SKILL.md + 双语触发词，repo 作用域 + 斜杠命令（/octospec-plan 等）。但处理的是代码工程产物（brief.md/context.yaml），与 Excel 无关——仅作「octo 系 skill 封装」的可核验范例收录，不是表格 skill。

五、评估方法调研（最佳实践）

一般流程/IO：输入 =（instruction + 输入工作簿 + 可能的多测试用例）；输出 = agent 产出工作簿；grader 比对产出 vs golden 给单题分 → 聚合类别分/总分。关键细节在 grader 设计（精确比对 vs 容差 vs judge） 与 可复现性（是否依赖真 Excel/COM/API key）。

5.1 SpreadsheetBench v1（online-judge 多测试用例）

来源：SpreadsheetBench: Towards Challenging Real World Spreadsheet Manipulation，Zeyao Ma et al.（人大/清华），NeurIPS 2024 Spotlight，arXiv:2406.14991 链接：https://arxiv.org/abs/2406.14991 · https://github.com/RUCKBReasoning/SpreadsheetBench 原文："SpreadsheetBench is built from 912 real questions gathered from online Excel forums... we propose a more reliable evaluation metric akin to online judge platforms, where multiple spreadsheet files are created as test cases for each instruction"

  • 设计：912 指令 / ~2729 测试用例（每指令 3 个）；单步操作；10 大类；分 cell-level（指定精确单元格）与 sheet-level。
  • grader：online-judge 式单元格比对，无 LLM judge；软限制（IOI 式部分分）/ 硬限制（ICPC 式全或无）。
  • 可复现性：全公开数据+代码；刻意「Software-independent Inference」不依赖 Excel API，可在 Excel/LibreOffice/WPS 跑。多模态不特殊处理。

5.2 SpreadsheetBench 2（工作流级 + 双 grader，含 VLM）

来源：SpreadsheetBench 2: Evaluating Agents on End-to-End Business Spreadsheet Workflows，Jian Zhu et al.（人大/Aptura/Shortcut/AfterQuery），arXiv:2606.29955，2026-06-29 链接：https://arxiv.org/abs/2606.29955 · https://github.com/RUCKBReasoning/SpreadsheetBench-2 原文（规模）："The benchmark contains 321 tasks; each instance averages 11.8 worksheets and requires 593.5 cell modifications... the best model achieves 34.89% overall task accuracy, and debugging accuracy is as low as 12.00%." 原文（grader）："Modification is a cell-level metric: for each task, we compute the fraction of target cells whose computed values match the golden file"；"Accuracy is a task-level metric: a task is scored 1 if every cell in the output spreadsheet matches the golden file (covering both target and non-target cells), and 0 otherwise." 原文（可视化）："GLM-4.6V ... as the judge to produce a binary pass / fail signal per criterion"，两维 "Data Correctness ... and Format Compliance (e.g., chart type, axis labels, color schemes)"。

  • 设计：321 工作流任务，真实商业数据（财报/filings），多表（均 11.8 sheet / 593.5 改动）。三大类 generation（financial modeling + template）/ debugging / visualization。
  • grader：非可视化 = 单元格比对（Modification 连续 + Accuracy 任务级全或无）；可视化 = VLM-as-judge（GLM-4.6V）逐条二值。
  • 可复现性：公开；沙箱「pre-installed with ... NumPy, Pandas, Matplotlib, openpyxl) and LibreOffice with its Python UNO bridge... No network access」。Claude Opus 4.6 34.89% / GPT-5.2 26.79 / Gemini 3.1 Pro 23.68。
  • （已另有专项报告） 本小节结论与此前《SpreadsheetBench v2 评估方法调研》一致：论文「every cell match」在代码里实为 1% 容差 + 99.8% regression 阈值 + 等价类。

5.3 WTM-BENCH（Microsoft，公式等价 + 结构匹配，刻意不用 VLM）

来源：Back to the Future: A workbook time machine for spreadsheet creation benchmarks，Mansi Uniyal et al.（Microsoft），COLM 2026，arXiv:2608.07873 链接：https://arxiv.org/abs/2608.07873 · https://github.com/microsoft/WTM-Bench 原文："From this corpus we curate WTM-Bench, a 150-task evaluation benchmark with queries at three levels of specificity... query specificity, agent orchestration, and interface API used to control spreadsheets play a big role in LLM performance"

  • 设计：150 任务，通过「逆向还原」成品工作簿为 (input, output, query) 三元组；三档 query 具体度。
  • grader：代码执行 + 加权结构匹配。公式——"Cell values are evaluated by computing formula results (via the Formulas library), so equivalent expressions that produce the same output receive full credit"（公式等价即容差）。图表——"chart type (40%...), series count (20%...), and series data references (40%: Jaccard overlap...). Axis labels, legend styling, and color choices are not evaluated"。透视表/条件格式各有子项评分。
  • 可复现性：公开（GitHub+HF）；后端含 "Python VBA OfficeJS"，部分配置需真 Excel。
  • 多模态：图表走结构匹配而非 VLM，且显式不评视觉样式——与 SB2 相反的设计选择。

5.4 WorkstreamBench（Columbia，整簿 LLM-judge rubric）

来源：WorkstreamBench: Evaluating LLM Agents on End-to-End Spreadsheet Tasks in Finance，Thomson Yen et al.（Columbia Business School），arXiv:2605.22664（后续版本更名 MBABench） 链接：https://arxiv.org/abs/2605.22664 原文："WorkstreamBench expects a complete multi-sheet workbook, and consequently employs a holistic evaluation centered on high-level quality... a taxonomy organized around three core dimensions: Accuracy, Format, and Formula."

  • 设计：228 金融任务，难度 1–5（WSP/FMWC/ModelOff 来源），从高层指令产出完整多表工作簿。
  • grader：经校验的 agentic LLM-judge 按 Accuracy/Formula/Format 三维 rubric 评分，可按维度选择性检查 sheet/range/公式/格式；校验结果 "the agentic judge attains 0.90 accuracy, 0.89 balanced accuracy, and 0.87 F1 score on 221 expert annotations"——judge 可靠性被量化，这是开放档评估的关键背书。
  • 可复现性：有 codebase；但 GUI arm（ChatGPT/Claude 产品）用 Playwright 驱动，需专有产品访问。

5.5 SheetBrain / SheetBench（结构复杂大表推理）

来源：SheetBrain: A Neuro-Symbolic Agent for Accurate Reasoning over Complex and Large Spreadsheets（CMU/浙大/Brown/Cambridge/MSR），arXiv:2510.19247 链接：https://arxiv.org/abs/2510.19247 · https://github.com/microsoft/SheetBrain 原文："we introduce SheetBench, a new benchmark targeting large, multi-table, and structurally complex spreadsheets... compiled from 69 case data selected from 11 public datasets, including HiTab, MiMoTable, ... SpreadsheetBench, SheetAgent..." - 设计：69 案例，取自 11 个公开数据集重标；分 Complex Tables / Multi-table Layouts / Large Sheets / Editing Operations。grader 用源数据集标签；执行走「Python sandbox + Excel helper toolkit」。多模态非重点。

负结果：DUET 多次检索未出现任何电子表格 benchmark，无可引链接，标原文片段不完整；"Domain-Spreadsheet" 非具名 benchmark，领域专项线索实为 Spreadsheet-RL（arXiv:2605.22642）、BlueFin（arXiv:2605.30907）、SpreadsheetArena（arXiv:2603.10002），可核验但本次未深抓引文。

六、综合排序（可复现性 / 价值 / 成熟度）

评分 H=高 / M=中 / L=低。可复现性看「公开代码数据 + 是否需专有工具」；价值看「性能/创新/指导意义」；成熟度看「同行评审 + 采用度」。

七、特殊情况（多模态是否被特殊处理，及其他）

多模态（图表/可视化）确实被当作特殊情况，且出现两条对立路线：

  • 路线 A：导图 + VLM-as-judge（SpreadsheetBench 2）。 图表无法用单元格比对，故 SB2 把图导出后交 VLM 按 rubric 逐条判。原文："GLM-4.6V ... as the judge to produce a binary pass / fail signal per criterion"，两维 Data Correctness / Format Compliance。代价：依赖 Windows 的 Excel/WPS COM 导图 + VLM API key，可复现性下降。
  • 路线 B：结构化匹配，刻意不用 VLM（WTM-BENCH）。 原文："chart type (40%...), series count (20%...), and series data references (40%: Jaccard overlap of reference strings). Axis labels, legend styling, and color choices are not evaluated." 用图表对象的结构属性做加权部分分，牺牲视觉保真换确定性与可复现。

启示：是否上 VLM 取决于「视觉保真」是否进评分目标。要稳定可复现→走结构匹配；要评到配色/样式→必须 VLM-judge。

其他特殊情况（均有原始来源）：

  1. 公式缓存 vs 公式字符串：openpyxl 以 data_only 读的是缓存值，未重算则为 None。Spreadsheet-RL 用 recalculate_and_read、Anthropic skill 用 recalc.py、SB2 用 LibreOffice UNO、WTM-BENCH 用 Formulas 库算公式结果——「先重算再判分」是全领域共识的前置步骤。
  2. 公式等价容差：WTM-BENCH 原文「equivalent expressions that produce the same output receive full credit」——评值不评串，避免把 =A1+A2 判负于 =SUM(A1:A2)。
  3. 保护未修改区域（回归）：SB2 的 Accuracy「covering both target and non-target cells」——不仅要改对该改的，还要求没碰坏不该动的。
  4. 专有工具依赖：真 Excel/COM（Spreadsheet-RL、PISTA、WTM 部分配置）、GUI 产品（WorkstreamBench 的 Playwright arm）会显著拉低可复现性。
  5. 大数据量/长链路：SB2 均 11.8 表 / 593.5 改动、SheetBench 专攻 Large Sheets——大工作簿下读表上下文裁剪（SheetAgent 给 Informer「3 example rows」+ schema）成为必需。

八、对 某表格 Agent 产品 的启示（线上 query 自动化评估 + 服务表格大数据处理）

8.1 评估方案：双档拆分 + judge 校准

线上 user query 多为开放答案、无单一 golden，直接套 SB2 的「任务级全或无」太严。建议：

  • 可判定档（有唯一正确锚点的 query）：复用 SB2/WTM 的「锚点单元格 + 公式等价容差 + 回归保护」自动判分。像 SB2 的 answer_position 一样，只圈定「必须正确的单元格/字段」，用 WTM 的「值等价即满分」做容差。连续分（命中率）优先于全或无。
  • 开放档（图表/排版/分析结论）：复用 WorkstreamBench 式 rubric + LLM/VLM-judge，且必须像它一样先用专家标注量化 judge 可靠性（它报到 0.90 acc 才敢用）。图表走 SB2 的 VLM-judge（若需视觉保真）或 WTM 的结构匹配（若只需确定性）。

8.2 一个改造样例

线上 query：「把这张销售表按区域汇总，算出各区域同比，并画一张柱状图」 → - 可判定档：各区域同比 写入指定单元格 → 用「锚点单元格 + 1% 值容差（公式等价）」自动判对错；并校验原始明细区（回归位）未被改坏。 - 开放档（图表）：rubric = {图表类型=柱状、X 轴=区域且齐全、数值绑定正确、标题含「同比」} → 若只需确定性走 WTM 结构匹配（type/series/data-ref Jaccard）；若要评配色/样式走 VLM-judge 二值。 - 聚合：可判定档出「精确率（连续）」，开放档出「rubric 通过率（连续）+ 校准后的二值达标」。

8.3 可直接迁移 vs 需改造

可直接迁移 需改造 / 不适用
评估 锚点式 golden、公式等价容差、回归保护、rubric+judge、judge 可靠性量化 任务级「全或无」过严→改连续分；SB2 唯一 golden→线上多解需先分档
Harness inspect→modify→verify 闭环、读并行/写串行、专用工具优于裸 Python、先重算后判 真 Excel/COM 依赖→大数据量线上服务宜用 LibreOffice UNO/Formulas 库无头重算
Skill SKILL.md 封装把「表格大数据处理」常见套路（透视/清洗/同比/建模）沉淀为可复用 skill；recalc.py 式 JSON 产出契约可直接接自动判分 >0.7 等人为阈值须用标注集重新校准；workspace skill 为不可信输入须做注入防护

服务「表格大数据处理」用户的落点：把高频 query 模式固化成 SKILL.md（如「同比/环比」「数据清洗」「透视汇总」「财务建模模板」），用「专用工具 + 先重算后校验」保证正确性，用「公式而非硬编码值」保证可维护——这正是 Anthropic xlsx skill 的硬性契约。
